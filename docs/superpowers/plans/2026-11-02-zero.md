# Zero Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Zero: a fast personal AI assistant with a Bun + TypeScript backend wrapping OpenCode, a Next.js web UI and a native Android app.

**Architecture:** A monorepo with three parts. The backend owns accounts, chats, memory and settings in SQLite, and talks to one long-running OpenCode server through `@opencode-ai/sdk/v2`, passing its token stream to clients as SSE. The web UI and the Android app are thin clients of one REST+SSE contract defined in Task 1. All engine access goes through an `Engine` interface so every backend test runs against a `FakeEngine`.

**Tech Stack:** Bun 1.4 (`bun:sqlite`, `bun test`, `Bun.password`), TypeScript, zod, `@opencode-ai/sdk` 1.19.5 (import from `/v2`), Next.js (App Router) + Tailwind v4 + lucide-react, Kotlin + Jetpack Compose + OkHttp + kotlinx.serialization + Room + DataStore, Gradle.

**Spec:** `docs/superpowers/specs/2026-11-02-zero-design.md`

## Global Constraints

- Dark theme only. Tokens verbatim: bg `#16181d`, surface `#1d2026`, raised `#23262d`, border `#2c3038`, border-strong `#3a3f49`, text `#e6e8ee`, muted `#8a8f9a`, accent `#5b8def`, accent-hover `#7aa3f2`, danger `#f2777a`, warning `#e5a54b`.
- 6px radius, 15px base text, 40px controls, 32px compact controls, Inter then system fonts, no external loads (no CDN fonts, images or scripts), focus ring 2px accent.
- Web search is the only tool the model may use. Memory is an internal capability, not a tool.
- Backend binds `0.0.0.0`; clients take a backend URL; Zero does no tunnel or TLS setup; Android allows cleartext HTTP to the configured URL.
- Provider keys live only on the server and are never returned to a client.
- Login has rate limiting; passwords are never logged or echoed.
- No extra model call on the answer path. Chat titles come from the first message text, not from a model.
- Settings screen holds exactly: backend URL, favorite models, connected providers, personalization (plus the Memory screen), account.
- No channels, voice, light theme, iOS, extra tools or extra providers.
- Every UI string lives in one strings file per client (web `web/lib/strings.ts`, Android `strings.xml`).

## Review Focus

1. Sending a message with no provider connected: the user sees a clear "connect a provider" prompt, not a hang or a raw error. (Task 7)
2. Stream dropped mid-answer (client disconnects, server restarts): the partial answer is saved and the chat reopens without corruption. (Task 5)
3. Very large photo or file attachment: rejected with a readable size message before any model call. (Task 6)
4. Wrong password repeated many times: locked out with a retry time, while the right password from another IP still works. (Task 3)
5. Backend URL typed with no scheme, a trailing slash, or unreachable host: the client normalizes it and says what failed. (Tasks 11, 15)
